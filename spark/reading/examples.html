JDBC partition calculator

A table of 20 million orders keyed by order_id, ids from 1 to 50 million. Pick how the ids are distributed (recent-heavy: busy recent periods; gappy: nothing between 10M and 40M; outliers: three test rows with id 999,999,999), set the bounds and partition count, and compare Spark's equal-width ranges with predicates built from quantiles. Each bar is one read task.

A partitioned JDBC read

orders = (spark.read.format("jdbc")
    .option("url", "jdbc:postgresql://replica.db:5432/sales")     # a replica, not the primary
    .option("dbtable", "(SELECT order_id, customer_id, amount, created_at FROM orders) o")
    .option("user", user).option("password", password)            # from a secret store
    .option("partitionColumn", "order_id")
    .option("lowerBound", 1).option("upperBound", 50_000_000)
    .option("numPartitions", 16)
    .option("fetchsize", 10_000)
    .option("customSchema", "amount DECIMAL(18,2)")
    .load()
    .where("created_at >= '2026-01-01'"))                          # pushed into every query

orders.explain()      # JDBCScan … PushedFilters: [IsNotNull(created_at), GreaterThanOrEqual(created_at,…)]

Select only the columns you need in dbtable: column pruning cuts network transfer as much as filters cut rows.

Quantile predicates for skewed keys

Ask the database for the boundaries once (cache them if the distribution is stable), then pass one predicate per partition:

N = 16
bounds_sql = f"""(SELECT bucket, MIN(order_id) AS lo FROM (
                   SELECT order_id, NTILE({N}) OVER (ORDER BY order_id) AS bucket FROM orders) x
                 GROUP BY bucket ORDER BY bucket) b"""
los = [r.lo for r in spark.read.jdbc(url, bounds_sql, properties=props).orderBy("bucket").collect()]

preds = [f"order_id < {los[1]}"] + \
        [f"order_id >= {los[i]} AND order_id < {los[i+1]}" for i in range(1, N - 1)] + \
        [f"order_id >= {los[N-1]} OR order_id IS NULL"]           # every row exactly once

orders = spark.read.jdbc(url, "orders", predicates=preds, properties={**props, "fetchsize": "10000"})
  • The boundary query sorts by an indexed column, which most databases do from the index, but it still touches every key. On huge tables use the database's statistics (histograms) or a sample.
  • The first and last predicates are open-ended, and NULLs go to one of them, so no row is lost.

String or UUID keys: hash predicates

# Oracle shown; PostgreSQL: abs(hashtext(id::text)) % 16, SQL Server: ABS(CHECKSUM(id)) % 16
preds = [f"MOD(ORA_HASH(customer_uuid), 16) = {i}" for i in range(16)]
customers = spark.read.jdbc(url, "customers", predicates=preds, properties=props)

Hash predicates spread rows evenly, but each query has to evaluate the hash on every row: 16 full scans. Fine on a replica for medium tables; for large ones, add a function-based index on the expression or partition on a different, indexed column.

API fan-out with retries and error rows

import time
import pandas as pd
from pyspark.sql import functions as F

TOKEN = dbutils.secrets.get("api", "token")      # read on the driver; shipped with the function, never log it
BASE = "https://api.example.com/v1/items"

def fetch_pages(batches):
    import requests
    from requests.adapters import HTTPAdapter
    from urllib3.util.retry import Retry
    s = requests.Session()
    s.mount("https://", HTTPAdapter(max_retries=Retry(
        total=5, backoff_factor=1, status_forcelist=[429, 500, 502, 503, 504])))   # honours Retry-After
    s.headers["Authorization"] = f"Bearer {TOKEN}"
    try:
        for pdf in batches:
            rows = []
            for p in pdf["page"]:
                try:
                    r = s.get(BASE, params={"page": int(p)}, timeout=15)
                    rows.append((int(p), r.status_code, r.text if r.ok else None,
                                 None if r.ok else r.text[:500], time.time()))
                except Exception as e:                     # still failing after retries: record it, don't fail the task
                    rows.append((int(p), -1, None, str(e)[:500], time.time()))
            yield pd.DataFrame(rows, columns=["page", "status", "body", "error", "fetched_at"])
    finally:
        s.close()

raw = (spark.range(1, 501).withColumnRenamed("id", "page")
            .repartition(10)                                # 10 concurrent callers (if 10 task slots are free)
            .mapInPandas(fetch_pages, "page long, status int, body string, error string, fetched_at double"))
raw.write.mode("append").saveAsTable("bronze.api_items_raw")   # call once; everything downstream reads this

items = (spark.table("bronze.api_items_raw").where("status = 200")
    .select(F.explode(F.from_json("body",
        "struct<data:array<struct<id:string,name:string,status:string>>>").data).alias("i"))
    .select(F.col("i.id").cast("int").alias("id"), "i.name", "i.status")
    .dropDuplicates(["id"]))                                   # offset paging can repeat rows
  • Classic compute can use pages_df.rdd.mapPartitions(fn) with the same body; mapInPandas also works on serverless and Spark Connect, where RDDs don't exist.
  • Pages that failed (status != 200) are retried by a second run over just those page numbers.
  • Speculation off for this job (spark.speculation=false, the open-source default) so slow tasks don't call the API twice.

A minimal Python data source (Spark 4.0+)

The same API fan-out, packaged so other jobs can use spark.read.format("pagedapi"). You decide the partitions; Spark runs read for each on an executor.

from pyspark.sql.datasource import DataSource, DataSourceReader, InputPartition

class PageRange(InputPartition):
    def __init__(self, start, end):
        self.start, self.end = start, end

class PagedApiReader(DataSourceReader):
    def __init__(self, options):
        self.options = options

    def partitions(self):                                   # runs on the driver
        pages, per = int(self.options["pages"]), int(self.options.get("pagesPerPartition", 50))
        return [PageRange(s, min(s + per, pages + 1)) for s in range(1, pages + 1, per)]

    def read(self, partition):                              # runs on executors, one call per partition
        import requests
        with requests.Session() as s:
            for p in range(partition.start, partition.end):
                r = s.get(self.options["url"], params={"page": p}, timeout=15)
                yield (p, r.status_code, r.text)

class PagedApi(DataSource):
    @classmethod
    def name(cls):
        return "pagedapi"
    def schema(self):
        return "page int, status int, body string"
    def reader(self, schema):
        return PagedApiReader(self.options)

spark.dataSource.register(PagedApi)
df = spark.read.format("pagedapi").option("url", BASE).option("pages", 500).load()
