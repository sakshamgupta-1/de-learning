Auto Loader to Bronze

raw = (spark.readStream.format("cloudFiles")
    .option("cloudFiles.format", "json")
    .option("cloudFiles.schemaLocation", "/chk/bronze_orders/_schema")    # inferred schema, versioned
    .option("cloudFiles.inferColumnTypes", "true")
    .option("cloudFiles.schemaHints", "amount DECIMAL(18,2), order_ts TIMESTAMP")
    .option("cloudFiles.useNotifications", "true")                        # or managed file events
    .option("cloudFiles.maxFilesPerTrigger", 2000)
    .load("s3://landing/orders/"))

(raw.withColumn("_source_file", F.col("_metadata.file_path"))
    .withColumn("_ingested_at", F.current_timestamp())
    .writeStream
    .option("checkpointLocation", "/chk/bronze_orders")
    .option("mergeSchema", "true")                    # let the Delta table gain new columns too
    .trigger(availableNow=True)
    .toTable("bronze.orders"))
  • Keep _source_file and _ingested_at in Bronze: they're how you trace and replay later.
  • Watch _rescued_data: a count of non-null rescued rows per batch is a cheap schema-drift alert.

Kafka with Avro and a schema registry

Open-source Spark: strip the header, pass the schema

from pyspark.sql.avro.functions import from_avro

reader_schema = open("schemas/orders-value.avsc").read()     # latest schema, fetched from the registry at deploy

orders = (spark.readStream.format("kafka")
    .option("kafka.bootstrap.servers", brokers)
    .option("subscribe", "orders")
    .option("maxOffsetsPerTrigger", 500_000)
    .load()
    .select(F.col("key").cast("string").alias("order_key"),
            from_avro(F.expr("substring(value, 6, length(value) - 5)"),   # skip magic byte + schema id
                      reader_schema, {"mode": "PERMISSIVE"}).alias("o"),
            "partition", "offset", "timestamp")
    .select("order_key", "o.*", "partition", "offset", "timestamp"))

This decodes every message with one reader schema. That's correct for messages written with older, compatible writer schemas only if the reader schema can resolve them, which BACKWARD compatibility guarantees. PERMISSIVE mode turns undecodable messages into nulls instead of failing; route them to a quarantine table.

Databricks: let from_avro use the registry

from pyspark.sql.avro.functions import from_avro

orders = (spark.readStream.format("kafka")
    .option("kafka.bootstrap.servers", brokers).option("subscribe", "orders").load()
    .select(from_avro(data=F.col("value"),
                      subject="orders-value",
                      schemaRegistryAddress="https://registry.example.com",
                      options={"confluent.schema.registry.basic.auth.credentials.source": "USER_INFO",
                               "confluent.schema.registry.basic.auth.user.info": secret})
            .alias("o"))
    .select("o.*"))

The Databricks version reads the schema id in each message and resolves it against the subject's schema, so you don't hard-code a schema. Check your runtime's documentation for the exact options.

Writing to Kafka

(alerts.select(F.col("account_id").cast("string").alias("key"),
               F.to_json(F.struct("*")).alias("value"))
       .writeStream.format("kafka")
       .option("kafka.bootstrap.servers", brokers)
       .option("topic", "fraud-alerts")
       .option("checkpointLocation", "/chk/fraud_alerts")
       .start())

At-least-once: a replayed batch is produced again. Give each message a stable id (here the key plus an alert id inside the value) so consumers can deduplicate.

Streaming a Delta change feed

# source table needs: ALTER TABLE silver.customers SET TBLPROPERTIES (delta.enableChangeDataFeed = true)
changes = (spark.readStream
    .option("readChangeFeed", "true")
    .option("startingVersion", 120)                  # new checkpoints only
    .table("silver.customers")
    .where("_change_type != 'update_preimage'"))     # keep inserts, post-update images, deletes

Each row carries _change_type, _commit_version and _commit_timestamp, so a downstream MERGE can apply deletes and order updates.

An idempotent MERGE upsert, with deletes

from delta.tables import DeltaTable
from pyspark.sql import Window

def apply_changes(batch, batch_id):
    w = Window.partitionBy("customer_id").orderBy(F.desc("_commit_version"))
    latest = batch.withColumn("rn", F.row_number().over(w)).where("rn = 1").drop("rn")
    (DeltaTable.forName(spark, "gold.customers").alias("t")
        .merge(latest.alias("s"), "t.customer_id = s.customer_id")
        .whenMatchedDelete(condition="s._change_type = 'delete'")
        .whenMatchedUpdateAll(condition="s._change_type != 'delete' AND s._commit_version > t._commit_version")
        .whenNotMatchedInsertAll(condition="s._change_type != 'delete'")
        .execute())

(changes.writeStream.foreachBatch(apply_changes)
        .option("checkpointLocation", "/chk/gold_customers")
        .trigger(availableNow=True).start())
  • One row per key before MERGE, keeping the latest change.
  • Version guard: the target stores _commit_version, so a replayed or older change never overwrites a newer one. That's what makes the MERGE idempotent.
  • Lakeflow's AUTO CDC implements the same logic declaratively, including out-of-order handling and SCD Type 2.
